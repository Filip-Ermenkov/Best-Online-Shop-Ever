CSP validation page

This is a permanent diagnostic page for verifying the project's strict Content Security Policy is actually blocking parser-inserted inline scripts that don't carry the per-request nonce. The page is static HTML served from frontend/public/csp-test.html and is therefore not rendered by Next.js — Next.js cannot auto-attach a nonce to the script tags below, so the only way they can execute is if the CSP allows them, i.e. if the CSP is misconfigured.

Open the browser DevTools Console before loading this page so you see the CSP violation messages as the browser blocks each test. Then read off the results.

Why the DevTools console can't be used for this test

The standard "paste a document.createElement('script') + appendChild into the console" test produces a false positive under 'strict-dynamic': the console is treated as a trusted script source, so anything it inserts inherits trust via strict-dynamic. That's by design. The test below uses parser-inserted inline scripts in the served HTML, which is the actual attack surface CSP is meant to block (stored XSS in product descriptions, comments, etc.).

Tests

Test 1 — parser-inserted inline <script>: pending
Test 2 — inline event handler (onclick attribute): click the button →
Test 3 — javascript: URL: click here click the link →

What you should see

If CSP is configured correctly:

  • Test 1 stays pending (the inline script can't update the marker).
  • Test 2's button click does nothing visible; clicking still leaves "click the button →".
  • Test 3's link click does nothing visible; clicking leaves "click the link →".
  • The DevTools Console shows three red "Refused to execute inline script" / "Refused to execute inline event handler" messages.

If any test changes to "BYPASSED" in red, the CSP isn't enforcing what this project's ARCHITECTURE.md §5.2 says it does — fix it before merging.

Run it

Visit http://localhost:3000/csp-test.html in dev, or https://duda1.bg/csp-test.html in production. Same expected output in both. (The proxy still applies the strict CSP to this static-file path because it's not in the matcher's exclusion list.)
